# Project Meridian Requirements Compliance

The [capstone brief](../Logistics/PROJECT_MERIDIAN_Capstone_Logistics_Intelligence_Real-Time_Tracking.docx) describes 8,768 shipment records. Verification used the [trainer-supplied mini pack](../Logistics/Data/README.md) of 141 shipment rows and 43 tracking records. The ADLS acceptance run added two synthetic events. The evidence covers functional behavior on the mini pack. Performance and correctness at full-dataset scale require a separate run.

## Verification scope

This folder was imported from a separate Project Meridian bundle. Its logs and the GitHub Actions link below are archived evidence from that bundle's earlier executions; they are not results from this Dell Upskilling repository or this implementation session. The [fresh local demonstration attempt](../evidence/meridian-final-demo-attempt.log) reached 141 input rows and 133 latest versions before Docker Desktop stopped responding. The batch job timed out before the ADLS replay stage. The [earlier ADLS recovery log](../meridian-adls-recovery-verification.log) documents a separate prior test. The root workflow [`../../.github/workflows/project-meridian-ci.yml`](../../.github/workflows/project-meridian-ci.yml) is configured for this repository and must run on GitHub before its hosted CI status can be marked successful.

## Execution environments

- **Local Docker Desktop and Kubernetes** ran the packaged batch job, Kafka fixture replay, PVC recovery, producer rollout and rollback, and failure diagnosis. The Delta upsert regression ran in an isolated Spark container.
- **Azure Databricks** ran the historical notebook and published the four KPI outputs. The plan uses a Unity Catalog volume for inputs and managed tables for outputs. The saved exports show KPI parity and the evolved Iceberg column.
- **Azure Data Lake Storage Gen2** held the streaming checkpoint, Iceberg tables, and Delta event audit for the cloud-storage acceptance test. Spark and Kafka still ran on local Kubernetes during that test.
- **GitHub-hosted Actions (upstream bundle only)** has an archived run at commit `1b7d12c0a56be37034cfbc24c6f123d5f7fbb217`: [upstream workflow run](https://github.com/ShanmukhaAaryasree/project-meridian/actions/runs/44895379150). This does not verify the current Dell Upskilling repository.

## Business requirements

| BR-03 Duplicate and conflicting records | The [batch notebook](../01_Shipments_Batch.scala) chooses shipment versions and resolves customer duplicates deterministically. | BR-04 Shipment relationships | The [batch notebook](../01_Shipments_Batch.scala) checks customer, carrier, origin hub, and destination hub references. | **Local Kubernetes** [batch results](../meridian-batch-kubernetes.log) include the reference checks in the final counts. **Azure Databricks** [carrier and lane KPI tables](../evidence/databricks-kpi-comparison.csv) show the resulting aggregates. |
